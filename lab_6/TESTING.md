# Лабораторная №6 «Unit tests»

## Исходный проект

Источник: https://github.com/bbtoji/ws-http-server,
исходный коммит `6c7fbf2` (`Update README.md`).

Проект содержит HTTP-обработчик страницы и асинхронный WebSocket-сервер.
Он хранит набор клиентов, рассылает дату и очищает соединения при отключении.
В тестах выполняется настоящий код `main.py`. Заменены внешние зависимости:
часы, ожидание, сетевые соединения и операции запуска серверов.

## Как устроены сложные тесты

### Параметризация формата даты

`test_broadcast_sends_date_json` выполняет один и тот же сценарий для четырёх
дат. Фикстура `frozen_time` заменяет часы, а `monkeypatch` устанавливает
конкретный момент. Проверяется декодированный JSON, включая поле `type`.
Ожидаемые даты заданы строками явно: тест не повторяет вычисление `strftime`
из проверяемой функции. Для сдачи это один тест, а не четыре.

### Ошибки WebSocket

`WebSocketStub` реализует только нужные серверу асинхронные методы `send` и
`wait_closed`. Он может сохранить отправленное сообщение, выбросить заданное
исключение или выполнить действие во время вызова. Так можно воспроизвести
отключение, не поднимая настоящий сервер. Сохранённые сообщения и счётчик
вызовов позволяют проверить наблюдаемое поведение.

### Проверка запуска

`test_main_configures_and_starts_servers` использует настоящий маршрутизатор
aiohttp, но заменяет запуск сети и фоновой задачи. Подставные функции
записывают вызовы; тест проверяет параметры и порядок действий, зарегистрированные
маршруты и сообщения о запуске. Это проверка взаимодействия с зависимостями,
а не реальное соединение через сеть.

### Проверка бесконечного цикла

`send_date` предназначена для бесконечной работы. Фикстура `run_broadcast`
заменяет её ссылку на `asyncio` объектом с управляемым `sleep`. После заданного
числа проходов он выбрасывает `CancelledError`. Таким образом тест вызывает
настоящую рассылку, но заканчивается без задержек. В остальных частях Python
модуль `asyncio` не заменяется.

Обычные функции тестов запускают корутины через стандартный `asyncio.run`.
Дополнительный фреймворк для асинхронных тестов не нужен.

## Изменения исходного кода

| Было | Стало | Причина |
| --- | --- | --- |
| `asyncio.run(main())` при любом импорте | Запуск только под `if __name__ == '__main__'` | pytest может импортировать функции без открытия портов и бесконечного ожидания |
| `clients.remove(...)` в двух местах | `clients.discard(...)` | Обработчик закрытия и рассылка могут оба удалить одно соединение |
| Голый `except:` | `except Exception:` | `CancelledError` наследуется от BaseException и должен прерывать задачу |

Проверки не скрывают ошибки через skip или xfail. Никакие строки исходного
кода не исключены из измерения. Из отчёта исключены тесты и виртуальные окружения.
Покрытие 100% не доказывает отсутствие всех дефектов: работа настоящих
сокетов, поведение JavaScript в браузере и нагрузка требуют других проверок.

## Команды проверки

Из корня самостоятельного проекта:

```bash
python -m pip install -r requirements.txt
python -m pytest --collect-only -q
python -m pytest -v --cov=. --cov-report=term-missing --cov-report=html
```

Эквивалентный запуск через coverage:

```bash
python -m coverage run -m pytest
python -m coverage report
```

HTML-отчёт после первой команды с `--cov-report=html`:
`htmlcov/index.html`.
