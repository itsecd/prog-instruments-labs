### Лабораторная работа №4 «Рефакторинг»

## TennisGameDefactored1
Code smells в первом классе:
1. **Нарушение SRP**: в классе, отвечающем за подсчет очков в игре, хранились поля, больше связанные с информацией о игроках         (`player1Name`, `self.p1points`). Поэтому, если в будущем у игроков появится больше характеристик (например, рейтинг), не придется отдельно добавлять эти поля в класс `TennisGameDefactored1`.
2. **Нарушение соглашения об именовании + магические значения**: все переменные были записаны в стиле camelCase. Для лучшей читаемости они были изменены под стиль snake_case. Дополнительно, были вынесены магические значения из условных операторов (`GAME_SCORE`, `POINTS_TO_WIN`), чтобы избавиться от ненужных операций.
3. **Extract Variable (Извлечение переменной)**: были извлечены значения `equal_points` и `leader` для уменьшения проверок в условных операторах if.
4. **Consolidate Conditional Expression (Объединение условных операторов)**: выделение переменной `leader` позволило объединить 4 условных оператора в 1.
5. **Избавление от неиспользованных переменных**: при добавлении в код условий для досрочного выхода (то есть, при добавлении в  каждый условный оператор `return`), изначальные переменные `result` и `tempScore` оказались незадействованными. Поэтому от них было решено избавиться.

## TennisGameDefactored2
Code smells во втором классе:
1. **Нарушение SRP**: выделение класса Player.
2. **Нарушение соглашения об именовании + магические значения**: переменные были изменены под стиль snake_case, добавлены `GAME_SCORE`и `POINTS_TO_WIN`.
3. **Extract Variable (Извлечение переменной)**: были извлечены значения `score_diff` и `leader` для уменьшения проверок в условных операторах if.
4. **Consolidate Conditional Expression (Объединение условных операторов)**: строки, наподобие таких
```python
if (self.p1points==0):
    result = "Love"
if (self.p1points==1):
    result = "Fifteen"
if (self.p1points==2):
    result = "Thirty"
if (self.p1points==3):
    result = "Forty"
```
были объединены с помощью словаря `GAME_SCORE`.\
5. **Избавление от ненужных проверок в условных операторах**: при добавлении в код условий для досрочного выхода, некоторые проверки оказались бесполезными. Например,
```python
    if (self.p1points == self.p2points and self.p1points < 4):
        return score
    if (self.p1points==self.p2points and self.p1points>3):
```
во втором if проверка на то, что у игрока очков больше чем 3 - лишняя.\
6. **Dead code**: в классе изначально было два метода, которые дальше по коду ни разу не использовались (`SetP1Score`, `SetP2Score`). После вынесения класса Player пришлось также избавиться от методов `P1Score` и `P2Score`, так как их задачи выполнял метод класса Player (`add_point`).

## TennisGameDefactored3
Code smells в третьем классе:
1. **Нарушение SRP**: выделение класса Player.
2. **Нарушение соглашения об именовании + магические значения**: переменные были переименованы так, чтобы было понятно их предназначение (вместо `n -> name`, `s -> score`); добавлены `GAME_SCORE`и `POINTS_TO_WIN`.
3. **Extract Variable (Извлечение переменной)**: были извлечены значения `score_diff` и `leader`.
4. **Избавление от тернарных операторов**: в данном классе использование тернарного оператора наоборот усложнило код, а также увеличило длину строк. Были заменены на условные операторы.
