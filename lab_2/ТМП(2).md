# Часть 1. Ревью `main.py` (Шифр простой подстановки)

## Общая оценка

Код рабочий, логика шифра реализована корректно, есть проверка расшифровки.
Однако есть проблемы с архитектурой, читаемостью, обработкой ошибок и потенциальной производительностью.

## 1.1. Дублирование кода шифрования и записи в файл (нарушение DRY)

**Тип проблемы:** нарушение принципа DRY.

Блок кода:

```python
encrypted = cipher.encrypt(TEXT)
with open('encrypted.txt', 'w', encoding='utf-8') as f:
    f.write(encrypted)
```

повторяется **4 раза** (после генерации ключа, загрузки ключа, генерации нового ключа, редактирования замены).
При изменении логики (например, добавлении резервной копии) придётся править в четырёх местах.

**Решение:** вынести в отдельную функцию.

```python
def save_encrypted(cipher, text, filename='encrypted.txt'):
    """Шифрует текст и сохраняет в файл."""
    encrypted = cipher.encrypt(text)
    with open(filename, 'w', encoding='utf-8') as f:
        f.write(encrypted)
    return encrypted
```

Использование:

```python
encrypted = save_encrypted(cipher, TEXT)
print("✓ Текст перешифрован")
```

## 1.3. Функция `read_text_from_file` слишком большая (цикломатическая сложность)

**Тип проблемы:** неоправданная цикломатическая сложность, нарушение SRP.

Функция содержит **более 10 ветвлений** (`if/else`, `try/except`, вложенные циклы).
Смешаны ответственности: вывод списка файлов, ввод, чтение, валидация.

**Решение:** разбить на несколько функций по принципу единственной ответственности.

```python
def list_txt_files():

    return [f for f in os.listdir('.') if f.endswith('.txt') and f not in excluded]


def choose_file():

    txt_files = list_txt_files()

    return filename


def read_text_from_file():
    """Читает текст из выбранного файла."""
    while True:
        filename = choose_file()
        if filename is None:
            return None
```

## 1.5. `exit()` внутри функции (нарушение декомпозиции)

**Тип проблемы:** нарушение декомпозиции и тестируемости.

Функция `read_text_from_file` вызывает `exit()`. Это делает функцию неизолированной:

```python
if choice.lower() == 'q':

    print("Программа завершена.")

```

## 1.6. Ручной сбор строк через `+=` в цикле (производительность)

**Тип проблемы:** потенциальная проблема производительности.

```python
result = ''
for char in text:
    result += self.encrypt_dict.get(char, char)
```

Конкатенация строк в цикле создаёт новую строку на каждой итерации — O(n²) по памяти.
Для больших текстов это заметно медленнее.

**Решение:** использовать `str.join` с генератором — O(n).

```python
def encrypt(self, text):
    """Шифрует текст."""
    return ''.join(self.encrypt_dict.get(char, char) for char in text)

def decrypt(self, text):
    """Расшифровывает текст."""
    return ''.join(self.decrypt_dict.get(char, char) for char in text)
```

## 1.7. Отсутствие проверки состояния ключа в `Cipher` (CUPID / читаемость)

**Тип проблемы:** нарушение принципа CUPID (predictable, idiomatic).

Класс `Cipher` не проверяет состояние словарей. Если вызвать `encrypt()` до `generate_key()`
или `set_key()`, словари пусты — текст вернётся без изменений, что вводит в заблуждение.

**Решение:** добавить проверку готовности ключа.

```python
def encrypt(self, text):
    if not self.encrypt_dict:
        raise ValueError("Ключ не задан. Вызовите generate_key() или set_key().")
    return ''.join(self.encrypt_dict.get(char, char) for char in text)
```

## 1.8. `show_key_sample` падает при малом размере ключа (логическая ошибка)

**Тип проблемы:** логическая ошибка в вычислении остатка.

```python
items = list(self.encrypt_dict.items())[:n]

```

## 1.9. `edit_mapping`: удаление из `decrypt_dict` без проверки (хрупкость)

**Тип проблемы:** потенциальная ошибка `KeyError`.

```python
old = self.encrypt_dict[orig]
```

Если словари рассинхронизированы, возникнет `KeyError`. Код хрупкий.

```python
old = self.encrypt_dict.pop(orig)
```

## 1.11. `save_key` использует кириллический маркер `ПРОБЕЛ` (логическая ошибка)

**Тип проблемы:** неоднозначный формат сериализации ключа.

Формат `orig -> enc` с заменой пробела на `ПРОБЕЛ` **неоднозначен**:
если в тексте встретится слово `ПРОБЕЛ`, оно будет ошибочно преобразовано в пробел при загрузке.

**Решение:** использовать `repr` + `ast.literal_eval`.

```python
import ast

def save_key(self, filename):
    with open(filename, 'w', encoding='utf-8') as f:
        f.write("# КЛЮЧ ШИФРОВАНИЯ\n")
        for original, encrypted in sorted(self.encrypt_dict.items()):
            f.write(f"{original!r} -> {encrypted!r}\n")

def load_key(self, filename):
    key_dict = {}
    with open(filename, 'r', encoding='utf-8') as f:
        for line in f:
            line = line.strip()
            if '->' in line and not line.startswith('#'):
                o, e = map(str.strip, line.split('->', 1))
                key_dict[ast.literal_eval(o)] = ast.literal_eval(e)
    self.set_key(key_dict)
```

# Часть 2. Ревью гибридной криптосистемы (RSA + Camellia)

## Общая оценка

Проект структурирован грамотно: разделение на модули (`asymmetric`, `symmetric`, `config`, `utils`, `encryptor`, `decryptor`, `key_generator`), наличие конфигураций, использование современной библиотеки `cryptography`. Логика гибридного шифрования реализована корректно: симметричный ключ Camellia шифруется RSA с OAEP/SHA-256, данные шифруются Camellia в режиме CBC со случайным IV.

Однако есть **серьёзные проблемы**, часть из которых — критические ошибки логики и безопасности. Ниже — детальный разбор.

---

## 🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 2.1. `encryptor.py` использует **закрытый** ключ для расшифровки симметричного ключа

**Тип проблемы:** логическая ошибка, нарушение модели угроз.

В `run_encryption` симметричный ключ расшифровывается **закрытым** ключом RSA:

```python
from src.asymmetric import decrypt_with_rsa
# ...
symmetric_key = decrypt_with_rsa(encrypted_key, private_key_path)
```

Это означает, что для **шифрования** данных пользователю нужен **приватный** ключ. Это в корне неверно: приватный ключ должен использоваться только для дешифрования. Если злоумышленник получит доступ к машине шифрования, он автоматически получит и приватный ключ, и сможет расшифровать всё.

**Решение:** для шифрования симметричного ключа должен использоваться **открытый** ключ.

```python
from src.asymmetric import encrypt_with_rsa

def run_encryption(input_file, public_key_path, encrypted_symmetric_key_path,
                   output_file, crypto_config):
    # ...
    symmetric_key = read_binary_file(symmetric_key_path)  # или взять из другого места
    encrypted_key = encrypt_with_rsa(symmetric_key, public_key_path)
```

**Замечание:** в `key_generator.py` уже есть строка:

```python
encrypted_key = encrypt_with_rsa(symmetric_key, public_key_path)
```

то есть ключ шифруется **открытым** ключом — что правильно. Но `encryptor.py` пытается его расшифровать **закрытым** — это несовместимо и противоречит логике.

---

### 2.2. Режим CBC без аутентификации (уязвимость к padding oracle / bit-flipping)

**Тип проблемы:** потенциальная проблема безопасности.

Camellia в режиме **CBC** не обеспечивает целостность данных. Активный злоумышленник может изменять байты шифротекста, что приведёт к предсказуемым искажениям в расшифрованном тексте (bit-flipping attack). Отдельно — уязвимость к **padding oracle**, если сообщения об ошибках паддинга различимы.

В `decryptor.py` ошибки `ValueError` от `unpad_data` явно отделяются от прочих:

```python
except ValueError as e:
    print(f"[ОШИБКА] Ошибка при расшифровке: {e}")
    print("  - Неправильный padding (данные были изменены)")
```

Это классический **padding oracle**: атакующий по разному поведению программы может побайтово восстановить открытый текст.

**Решение:** использовать **AEAD-режим** (например, GCM или CCM) вместо CBC. Тогда проверка целостности встроена, а ошибки не различаются.

```python
from cryptography.hazmat.primitives.ciphers.aead import CamelliaGCM

def encrypt_with_camellia(data, key, crypto_config):
    nonce = os.urandom(12)
    camellia = CamelliaGCM(key)
    return nonce + camellia.encrypt(nonce, data, None)

def decrypt_with_camellia(encrypted_with_nonce, key, crypto_config):
    nonce = encrypted_with_nonce[:12]
    ct = encrypted_with_nonce[12:]
    camellia = CamelliaGCM(key)
    return camellia.decrypt(nonce, ct, None)
```

Тогда `utils.pad_data` / `unpad_data` становятся не нужны.

### 2.3. Приватный ключ сохраняется без пароля

**Тип проблемы:** потенциальная проблема безопасности.

```python
encryption_algorithm=serialization.NoEncryption()
```

Приватный ключ лежит на диске в открытом виде. Любой, кто получит доступ к файлу, сможет расшифровать все данные.

**Решение:** шифровать приватный ключ паролем (например, через `BestAvailableEncryption`):

```python
from cryptography.hazmat.primitives import serialization

def save_private_key(private_key, filepath, password: bytes | None = None):
    if password:
        enc = serialization.BestAvailableEncryption(password)
    else:
        enc = serialization.NoEncryption()
    pem = private_key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=enc
    )
    write_binary_file(filepath, pem)
```

И в `load_private_key` — принимать пароль.

### 2.4. `configure_paths` итерируется по ключам словаря без валидации ввода

**Тип проблемы:** UX + потенциальная ошибка.

```python
for key in settings_dict.keys():
    new_value = input(f"  {key} [{settings_dict[key]}]: ").strip()
    if new_value:
        settings_dict[key] = new_value
```

Пользователь может ввести произвольную строку. Никакой проверки, что путь существует, что это файл, что директория доступна для записи. Позже `read_text_file` упадёт с `FileNotFoundError`.

**Решение:** добавить валидацию пути и подсказку.

```python
def configure_paths(settings_dict, settings_file):
    print("\n--- НАСТРОЙКА ПУТЕЙ ---")
    for key, current in settings_dict.items():
        new_value = input(f"  {key} [{current}]: ").strip()
        if not new_value:
            continue
        parent = os.path.dirname(new_value) or '.'
        if not os.path.isdir(parent):
            print(f"  ⚠ Директория '{parent}' не существует. Значение не сохранено.")
            continue
        settings_dict[key] = new_value
    save_settings(settings_dict, settings_file)
    return settings_dict
```

### 2.5. Дублирование проверок `os.path.exists` в `interactive_mode`

**Тип проблемы:** нарушение DRY.

В `main.py` два почти одинаковых блока:

```python
if not os.path.exists(settings_dict['encrypted_symmetric_key']):
    print(f"\n[ОШИБКА] Зашифрованный симметричный ключ не найден: ...")
    print("Сначала выполните режим 1 (Генерация ключей).")
    input("\nНажмите Enter для продолжения...")
    continue
```

повторяется в режимах 2 и 3 (а в режиме 3 ещё и проверка `encrypted_file`).

**Решение:** вынести во вспомогательную функцию.

```python
def require_files(paths: list[tuple[str, str]], hint: str) -> bool:
    """Проверяет наличие файлов. paths — список (путь, человекочитаемое имя)."""
    missing = [(p, name) for p, name in paths if not os.path.exists(p)]
    if missing:
        for path, name in missing:
            print(f"\n[ОШИБКА] {name} не найден: {path}")
        print(hint)
        input("\nНажмите Enter для продолжения...")
        return False
    return True
```

Использование:

```python
if not require_files(
    [(settings_dict['encrypted_symmetric_key'], "Зашифрованный симметричный ключ")],
    "Сначала выполните режим 1 (Генерация ключей)."
):
    continue
```

### 2.7. `error_occurred` в `decryptor.py` — мёртвый код

**Тип проблемы:** мёртвый код.

```python
    print(...)
    error_occurred = True
    return       # ← выход из функции сразу
# ...
if error_occurred:
    print("[НЕУДАЧА] Дешифрование завершено с ошибками!")
else:
    print("[ГОТОВО] Дешифрование завершено успешно!")
```

Все ветки с `error_occurred = True` заканчиваются `return`. Значит, до финальной проверки `if error_occurred` управление дойдёт **только** если ошибок не было. То есть `error_occurred` всегда `False` в этой точке. Флаг бесполезен.

**Решение:** убрать флаг и упростить финал.

```python
print("\n" + "="*60)
print("[ГОТОВО] Дешифрование завершено успешно!")
print("="*60)
```

### 2.8. `read_text_file` и `read_binary_file` — идентичные функции

**Тип проблемы:** дублирование, избыточность.

```python
def read_binary_file(filepath: str) -> bytes:
    with open(filepath, 'rb') as f:
        return f.read()

def read_text_file(filepath: str) -> bytes:
    with open(filepath, 'rb') as f:
        return f.read()
```

Обе читают байты. То же самое с `write_binary_file` / `write_text_file`.

**Решение:** оставить одну пару функций — `read_file` / `write_file`.

### 2.9. `main.py`: `args.interactive or len(sys.argv) == 1` — хрупкая логика

**Тип проблемы:** логическая ошибка.

```python
if args.interactive or len(sys.argv) == 1:
    interactive_mode(args.crypto_config, args.settings)
else:
    parser.print_help()
```

Если пользователь запустит `python main.py --crypto-config custom.json`, но без `--interactive`, программа просто **напечатает справку** и выйдет. Это неочевидно и бесполезно — можно было бы запустить интерактивный режим с указанным конфигом.

**Решение:** сделать `--interactive` значением по умолчанию, а неявный запуск без аргументов — тоже интерактивным. Иначе — явный CLI-режим с подкомандами.

```python
parser.add_argument('--non-interactive', action='store_true',
                    help='Запуск без меню (требует --mode)')
parser.add_argument('--mode', choices=['gen', 'enc', 'dec'],
```

### 2.10. `crypto_config` и `settings` дублируют структуру в сообщениях об ошибках

**Тип проблемы:** нарушение DRY.

В `config.py` при `FileNotFoundError` жёстко прописан JSON-шаблон:

```python
raise FileNotFoundError(
```

**Решение:** вынести шаблоны в константы или читать из встроенного `dict` и сериализовать.

```python
DEFAULT_CRYPTO_CONFIG = {

    "symmetric_key_size": 32,
    "rsa_key_size": 2048,
    "rsa_public_exponent": 65537,
}

def crypto_config(config_file: str) -> dict:
    if not os.path.exists(config_file):
        template = json.dumps(DEFAULT_CRYPTO_CONFIG, indent=4, ensure_ascii=False)
        raise FileNotFoundError(
            f"Файл {config_file} не найден.\n"
            f"Создайте его с содержимым:\n{template}"
        )
```

### 2.13. `save_settings` печатает в stdout — смешение ответственностей

**Тип проблемы:** нарушение декомпозиции.

```python
import logging
```

### 2.15. `crypto_config.json`: `rsa_public_exponent: 65537` — нет валидации

**Тип проблемы:** читаемость, безопасность.

В JSON `65537` — обычное число. В `crypto_config()` оно читается как `int`. Стоит явно валидировать допустимые значения (например, `65537` или `3`).

```python
ALLOWED_EXPONENTS = {3, 65537}

def validate_crypto_config(cfg: dict) -> None:
    if cfg.get('rsa_public_exponent') not in ALLOWED_EXPONENTS:
        raise ValueError("rsa_public_exponent должен быть 3 или 65537")
    if cfg.get('block_size') not in (16,):
        raise ValueError("block_size должен быть 16 для Camellia")
```

### 2.19. `symmetric.py`: `decrypt_with_camellia` не проверяет длину входных данных

**Тип проблемы:** потенциальная ошибка.

```python
iv = encrypted_data_with_iv[:block_size]
encrypted_data = encrypted_data_with_iv[block_size:]
```

Если файл короче `block_size`, IV будет неполным, а `encrypted_data` — пустым. `decryptor.finalize()` бросит исключение, но сообщение будет невнятным.

**Решение:** явная проверка.

```python
if len(encrypted_data_with_iv) < block_size * 2:
    raise ValueError(
        f"Слишком короткие данные: {len(encrypted_data_with_iv)} байт, "
        f"минимум {block_size * 2}"
    )
```

### 2.20. Отсутствие `__init__.py` в `src/` (предположительно)

**Тип проблемы:** структура пакета.

Если `src/` не содержит `__init__.py`, то импорты `from src.config import ...` работают только потому, что Python 3 поддерживает namespace-пакеты. Это неявно и может привести к проблемам при установке.

**Решение:** добавить `src/__init__.py` (пустой или с `__all__`).
