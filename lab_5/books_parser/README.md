# Лабораторная работа №5 - Логирование

## Исходный проект

Использован собственный парсер книг после рефакторинга в ЛР №4:

https://github.com/Dun4uv/prog-instruments-labs/tree/lab4/lab_4/books_parser

Программа извлекает сведения о книгах из сохранённой HTML-страницы
Books to Scrape и записывает их в CSV.

До внедрения логирования основные модули содержали 173 строки:
main.py - 29, parser.py - 119, storage.py - 25.
В исходной версии использовался только вывод результата и ошибок
через print. Исходное состояние сохранено отдельным коммитом.

## Реализация логирования

Используется стандартная библиотека Python logging.
Настройка вынесена в logging_config.py.

Формат основан на «Авторском рецепте» из лекции:
фиксированные поля записи, код события на английском языке
в верхнем регистре и дополнительные данные в JSON.

Каждая строка содержит шесть полей, разделённых табуляцией:

1. Дата и время UTC в формате ISO 8601.
2. Уровень сообщения.
3. Код события.
4. Имя приложения - books_parser.
5. Имя компьютера.
6. JSON с данными события.

Журнал сохраняется в logs/app.log в кодировке UTF-8.
Новые записи добавляются в конец файла.
Файлы *.log исключены из Git существующим .gitignore.

Логгеры books_parser.main, books_parser.parser и books_parser.storage
передают события общему логгеру books_parser.
Повторная настройка закрывает и заменяет прежние обработчики,
предотвращая дублирование записей.

## Точки логирования

| Событие | Уровень | Содержание |
| --- | --- | --- |
| APP_STARTED | INFO | Запуск, пути входного HTML и выходного CSV |
| INPUT_READ | INFO | Успешное чтение HTML, путь и количество символов |
| CARDS_FOUND | INFO | Количество найденных карточек |
| BOOK_PARSED | DEBUG | Успешный разбор книги, номер карточки, ссылка и рейтинг |
| CSV_WRITE_STARTED | DEBUG | Начало записи CSV, путь и количество записей |
| CSV_SAVED | INFO | Успешное завершение записи CSV |
| APP_FINISHED | INFO | Успешное завершение программы, количество книг и код 0 |
| APP_FAILED | ERROR | Ошибка обработки, пути файлов, тип исключения и traceback |

Реализовано 8 различных точек логирования.

При ошибке logger.exception записывает трассировку исключения.
Форматтер помещает её в JSON-поле traceback, поэтому одна запись
журнала остаётся одной строкой.

## Структура проекта

- main.py - запуск программы и обработка ошибок.
- parser.py - извлечение и проверка полей книг.
- storage.py - запись CSV.
- logging_config.py - настройка логгера и форматирование записей.
- test_main.py - 7 существующих тестов парсера.
- test_logging.py - 4 теста логирования.
- catalogue.html - сохранённый каталог с 20 книгами.
- sample.html - пример с двумя карточками.
- books.csv - результат обработки каталога.
- requirements.txt - указание на использование стандартной библиотеки.

## Запуск

Требуется Python 3.10 или новее. Сторонние библиотеки не нужны.

Из корня репозитория:

```bash
py lab_5/books_parser/main.py
```

Результаты находятся в каталоге lab_5/books_parser:

- books.csv - извлечённые данные;
- logs/app.log - журнал событий.

## Проверка

```bash
py -m unittest discover -s lab_5/books_parser -v
```

Все 11 тестов прошли.

Существующие тесты проверяют разбор HTML, обработку ошибок
и сохранение данных в CSV.

Новые тесты проверяют:

- состав полей, время UTC и сохранение специальных символов в JSON;
- сохранение истории и отсутствие дублирования после повторной настройки;
- события успешного запуска и побайтовое совпадение CSV с образцом;
- запись ошибки с traceback и сохранность предыдущего CSV.

Тесты логирования используют временные каталоги.
